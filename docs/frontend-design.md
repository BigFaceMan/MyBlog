# 前端设计

## 1. 技术栈

- Vue 3
- Vue Router 4
- Pinia
- Vue I18n
- Element Plus
- Vite
- TypeScript
- `markdown-it` + `highlight.js`

前端定位是单页应用，同时承载两类场景：

- 面向访客的博客站点
- 面向作者的文章管理后台

## 2. 页面结构设计

### 2.1 全局骨架

应用入口在 `frontend/src/main.ts`，完成：

- 创建 Vue 应用
- 注册 Pinia、Router、I18n
- 按需注册 Element Plus 组件
- 注入全局样式

根组件 `App.vue` 的结构很简单：

- 固定头部 `AppHeader`
- 主内容区域 `RouterView`
- 应用启动时预加载站点资料 `siteStore.loadProfile()`

这意味着站点名称、头像、公告等基础信息在大多数页面都是共享数据。

### 2.2 页面布局

核心布局组件是 `PageShell.vue`，采用双栏网格：

- 主内容区
- 右侧侧栏

默认博客页面带侧栏，后台页面和 404 / About 等页面可以关闭侧栏。侧栏包括：

- 作者卡片
- 公告卡片
- 最近文章
- 分类与标签聚合

这种布局让“内容流”与“站点导航/聚合信息”保持分离，符合博客阅读场景。

## 3. 路由设计

路由集中在 `frontend/src/router/index.ts`。

### 3.1 公开页面

- `/`: 首页文章列表
- `/articles/:slug`: 文章详情
- `/categories` 和 `/categories/:slug`: 分类页
- `/tags` 和 `/tags/:slug`: 标签页
- `/archive`: 归档页
- `/search`: 搜索页
- `/about`: 关于页

### 3.2 管理页面

- `/admin`: 文章列表管理
- `/admin/articles/new`: 新建文章
- `/admin/articles/:id/edit`: 编辑文章

### 3.3 路由策略

- 所有页面组件使用动态导入，降低首屏打包体积
- 切页时统一滚动到顶部
- 后台和前台共用同一 router，当前没有鉴权守卫

## 4. 组件分层

### 4.1 Layout 层

- `AppHeader.vue`: 顶部导航，支持桌面菜单和移动端抽屉菜单
- `PageShell.vue`: 页面骨架和侧栏布局

### 4.2 Blog 展示层

- `ArticleList.vue`: 列表容器
- `ArticleCard.vue`: 文章卡片
- `ArticleMeta.vue`: 时间、分类、标签元信息
- `MarkdownRenderer.vue`: Markdown 渲染与代码高亮

### 4.3 Sidebar 层

- `AuthorCard.vue`
- `AnnouncementCard.vue`
- `RecentPostsCard.vue`
- `TaxonomyCard.vue`

### 4.4 Common 层

- `StateBlock.vue`: 统一加载态、错误态、空态

这种分层方式比较实用：页面组件主要处理“取什么数据、什么时候取”，展示细节下沉到组件层。

## 5. 数据访问设计

前端 API 访问层位于 `frontend/src/api`。

### 5.1 `http.ts`

`request()` 是统一请求入口，负责：

- 读取 `VITE_API_BASE_URL`
- 发起 `fetch`
- 解析统一响应结构
- 在 HTTP 失败或业务 `code !== 0` 时抛出 `HttpError`

### 5.2 `blog.ts`

封装公开站点的查询接口：

- 站点信息
- 文章列表
- 文章详情
- 分类/标签列表
- 分类/标签文章列表
- 归档
- 搜索

### 5.3 `admin.ts`

封装后台管理接口：

- 后台文章列表
- 文章详情
- 新建文章
- 更新文章
- 更新发布状态
- 删除文章
- 创建标签

这种 API 分层清楚地区分了“访客读接口”和“作者写接口”。

## 6. 状态管理设计

当前只有一个显式 Pinia store：`siteStore`。

它保存：

- 站点 profile
- 加载状态
- 错误信息

设计意图是把跨页面共享、变化频率低的站点基础信息缓存起来，而不是把所有页面数据都堆进 store。

其他页面大多使用局部 `ref/reactive` 状态，优点是：

- 简单
- 页面自洽
- 调试成本低

代价是：

- 最近文章、分类、标签等在多个组件里会重复请求
- 还没有做跨页面缓存和失效策略

## 7. 交互设计

### 7.1 首页和列表页

- 首页展示分页文章流
- 分类页和标签页支持聚合导航 + 对应文章结果
- 搜索页通过路由 query `q` 持久化搜索条件
- 归档页按年月组织文章，强调时间线浏览

### 7.2 文章详情页

- 头图 + 标题 + 元信息 + Markdown 内容
- 渲染层禁用原始 HTML，降低内容注入风险
- 支持代码高亮

### 7.3 后台编辑页

编辑器页是当前前端交互最重的部分，包含：

- 标题、slug、摘要、封面、分类、标签、正文编辑
- slug 自动生成
- 新标签即时输入
- 发布/草稿状态切换
- 右侧封面预览
- 右侧 Markdown 实时预览

这说明当前后台设计强调“单页完成编辑与预览”，而不是拆成多步流程。

## 8. 视觉设计

### 8.1 风格基调

全局视觉采用：

- 浅色卡片式布局
- 绿色作为主品牌色
- 柔和阴影和半透明背景
- 大标题、块状内容区、明显的留白

基础设计变量在 `frontend/src/styles/variables.css` 中定义，包括：

- 页面背景
- 卡片背景
- 文本层级
- 边框颜色
- 主色与 hover 色
- 阴影体系
- 动画时长

### 8.2 全局背景

`base.css` 使用了多个渐变和几何装饰块作为背景。设计目的不是极简纯白，而是让博客首页和内容页有轻微品牌氛围。

### 8.3 组件视觉

- 文章卡片支持 hover 浮起和边框高亮
- 分类卡片、标签胶囊、统计卡片都采用统一圆角和轻阴影
- 顶部导航为毛玻璃粘性头部
- Element Plus 被二次主题化，尽量与站点卡片风格一致

### 8.4 响应式

当前主要响应式策略：

- 顶部导航在小屏切到抽屉菜单
- `PageShell` 在窄屏下从双栏退化到单栏
- 文章卡片在小屏下由左右布局变为上下布局
- 搜索表单、后台筛选区、关于页统计区在小屏下改单列

## 9. 国际化设计

I18n 当前只配置了 `zh-CN`，但结构已经按命名空间组织：

- `common`
- `nav`
- `sidebar`
- `page`
- `state`

这为后续增加英文版保留了接口，但目前仍有部分文案是中文和英文混用，尚未完全统一。

## 10. 当前前端实现的优点与风险

### 优点

- 结构直接，页面职责清晰
- 视觉风格统一，博客感比较明确
- 后台编辑器已经具备 MVP 所需的核心交互
- 统一错误态/加载态降低了页面重复实现成本

### 风险和不足

- 缺少登录态和路由权限控制
- 多个侧栏组件存在重复请求
- 没有 SSR / SSG，对 SEO 和首屏直出不友好
- 管理端和展示端混在一个 SPA，未来权限复杂时耦合会变高
- Markdown 渲染未接入更严格的内容安全策略和图片处理能力

## 11. 前端演进建议

- 把分类、标签、最近文章等聚合数据收敛到 store 或查询缓存层
- 为后台增加鉴权、路由守卫和会话状态
- 如果博客偏内容分发，考虑引入 SSR / SSG
- 为编辑器增加自动保存、草稿恢复、封面上传和发布确认能力
- 抽离共享查询逻辑，减少页面内重复的 loading/error 模板代码
